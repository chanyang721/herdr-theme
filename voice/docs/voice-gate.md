# 목소리 판정: 구조, 막는 경로, 시험

받아쓰기에 주변 사람 말이 섞여 전송되는 것을 어떻게 막는지 정리한다. 시험은 모두 공개 한국어 음성(Zeroth-Korean 26명)과 합성 조건으로 했다. 사용자 녹음은 쓰지 않는다.

## 요약

- 화자 구분 모델 자체보다 **판정기가 듣지 못한 말**이 새는 경로가 더 크다. 판정 구간이 하나도 없는 녹음은 점수로 막을 근거가 없다.
- 그래서 **전송 시점 검사**를 둔다. 받아쓴 글자 수를 그 녹음 안에서 들린 본인 말 시간이 설명하지 못하면 `UserPromptSubmit` hook 이 전송을 막는다.
- 함께 VAD 를 더 민감하게 해서 작은 말소리도 판정기가 듣게 한다.

## 구조

| 항목 | 내용 |
|---|---|
| 특징 | 3D-Speaker ERes2Net base, 512차원, 코사인 유사도 |
| 학습 데이터 | 등록한 말과, 전송된 받아쓰기 구간 중 이미 본인 점수 `pool_score` 이상인 구간의 임베딩(`voice-pool-<마이크>.jsonl`, 최근 10분). 원본 음성 없음 |
| 기준값 | 기본 `default_threshold`(0.4), 자동 상한 `max_threshold`(0.5). 마이크별 고정값은 사용자 설정. 1초 미만 구간은 판단 보류 |
| 판정 시점 | 말 덩어리가 끝날 때마다 `voice-segments.jsonl` 에 기록. 받아쓰기 글과는 시간으로만 연결 |
| 말 감지 | Silero VAD. 기준 `vad_threshold`(0.35), VAD 입력만 `vad_gain` 배 증폭(임베딩은 원래 음량). 등록이 마이크별 증폭을 정한다 |

사람마다 다른 값(자동 전송 마이크, 마이크별 기준값·증폭)은 저장소가 아니라 `voice.local.json` 에 둔다. README 의 "설정 바꾸기" 참고.

## 새는 경로

1. **판정기가 못 듣는다.** 시험에서 기본 VAD 는 -52 dBFS 부근부터 말을 놓치고, 소음이 -51 dBFS 면 -46 dBFS 말의 28%만 듣는다. Claude Code 의 받아쓰기는 그보다 작은 말도 받아쓴다.
2. **오래된 본인 말이 근거가 된다.** 녹음 전의 말로 전송 여부를 고르면 그 녹음과 무관한 판정을 쓰게 된다. 판단은 녹음 시작 이후의 말로 한정한다.
3. **Claude Code 가 스스로 전송한다.** 무음 시간 초과와 F8 정지는 플러그인의 판단을 거치지 않는다. 그래서 마지막 관문을 hook 으로 둔다.
4. **방 전체를 듣는 마이크.** 노트북 내장 마이크로 학습하면 옆 대화를 본인으로 배울 수 있다. 자동 전송은 사용자가 허용한 마이크(`auto_send_devices`)에서만 하고, 등록은 내장 마이크를 넣지 않는다.

## 전송 규칙

| 구성 | 내용 |
|---|---|
| `rust/src/voice/policy.rs` | 녹음 창의 본인 발화가 0보다 크고, 다른 목소리 이상이고, 글자 수를 설명하고(`max_chars_per_second`), 평균 점수 `dictation_score` 이상 |
| `herdr-theme voice_submit_hook` | 모든 전송을 `UserPromptSubmit` 에서 검사. 막힌 글은 그 기기의 `voice-blocked.jsonl` 에만 남긴다 |
| 예외 | 1초 안의 실제 키 입력(직접 Enter), `hc send` 메시지, 슬래시 명령, 최근 녹음하지 않은 pane |
| 판정기 이상 | 판정기 정지, 등록 없음, 허용되지 않은 마이크면 막는다(직접 Enter 는 통과) |
| `herdr-theme focus_queue` | 녹음 시작 시각 기록, F8 판단을 그 시각 이후 말로 한정, hook 이 막아 되돌아온 글을 지움 |

hook 동작:

- 대기열로 들어가는 메시지도 입력 즉시 hook 이 돈다. 꺼내질 때가 아니다.
- 종료 코드 2 는 전송을 막고 글을 입력창으로 되돌린다. 안 지우면 다음 말과 합쳐지므로 리스너가 지운다.
- 실제 키 시각은 권한 없이 읽힌다(`CGEventSourceSecondsSinceLastEventType`). pane 으로 보낸 키는 세지 않는다.

## 화자 모델 후보

원거리 조건: 다른 사람이 20 dB 작게, 잔향과 소음이 있는 채 들린다. 등록 45초, 본인 시도 208회, 타인 시도 5,200회. 본인 시도가 208회라 1% 안팎의 차이는 구분되지 않는다. 메모리는 ONNX 런타임 포함 프로세스 최대 RSS 이고, Apple Silicon CPU 2스레드 기준이다(`herdr-theme voice_eval_models`).

| 모델 | 크기 | 메모리 | 3초 처리 | EER 1초 | EER 2초 | EER 3초 | 3초 본인 거부(타인 통과 0.1%) |
|---|---|---|---|---|---|---|---|
| ERes2Net base (사용 중) | 40 MB | 196 MB | 31 ms | 6.7% | 3.4% | 1.9% | 1.9% |
| CAM++ zh_en advanced | 28 MB | 152 MB | 14 ms | 7.7% | 2.9% | 1.4% | 1.4% |
| ERes2Net base 200k | 40 MB | 196 MB | 38 ms | 7.7% | 4.3% | 1.4% | 2.4% |
| ERes2NetV2 | 71 MB | 312 MB | 57 ms | 6.7% | 3.8% | 1.4% | 1.4% |
| TitaNet small | 40 MB | 187 MB | 13 ms | 7.7% | 3.8% | 1.9% | 1.9% |
| WeSpeaker ResNet34 LM | 27 MB | 124 MB | 26 ms | 12.0% | 8.5% | 4.7% | 12.0% |
| WeSpeaker CAM++ LM | 29 MB | 151 MB | 18 ms | 45.6% | 17.3% | 50.5% | 100% |

- 모델 차이는 시험 오차 안이고, 바꾸면 목소리를 다시 등록해야 하므로 바꾸지 않는다. 바꾼다면 더 빠르고 가벼운 CAM++ zh_en advanced 가 후보다.
- 영어로 학습한 WeSpeaker 두 모델은 한국어에서 눈에 띄게 나쁘다. CAM++ LM 의 수치는 정상 범위가 아니어서 입력 방식이 맞지 않았을 가능성이 있다.
- 말 길이가 정확도를 가장 크게 바꾼다. 1초 EER 은 3초의 3~5배다. 그래서 구간 하나가 아니라 받아쓰기 전체의 평균 점수를 함께 본다.
- 같은 사람의 같은 녹음 세션 데이터이고 실제 헤드셋 경로가 아니므로 실사용 값은 이보다 나쁠 수 있다. 모델 간 비교로만 쓴다.

## 판정기 체인 합성 시험

`herdr-theme voice_eval_gate_chain`. 실제 VAD·임베딩 코드, 소음 -51 dBFS, 시나리오별 48건. "기존" 은 Silero 기본 VAD, "변경" 은 위 VAD 설정과 전송 규칙이다.

| 조건 | 기존: 구간 없음 | 기존: 구간에서 본인 판정 | 변경: 구간 없음 | 변경: 구간에서 본인 판정 | 변경: 전송 규칙 통과 |
|---|---|---|---|---|---|
| 본인 -26 dB | 0 | 48 | 0 | 48 | 48 |
| 타인 -36 dB | 0 | 4 | 0 | 2 | 0 |
| 타인 -46 dB | 6 | 1 | 0 | 2 | 1 |
| 타인 -52 dB | 44 | 0 | 0 | 1 | 0 |

타인 144건 중 1건(평균 0.51)이 통과했다. 비슷한 목소리는 여전히 샐 수 있다.

## VAD

`herdr-theme voice_eval_vad`, 60문장. 표는 들린 말의 비율이고, 소음만 있는 1분에서 잘못 잡힌 말은 모든 설정에서 0초였다.

| 소음 | 설정 | -26 dB | -46 dB | -52 dB |
|---|---|---|---|---|
| -65 dBFS | 기준 0.5 | 82% | 91% | 79% |
| -65 dBFS | 기준 0.35, +20 dB | 91% | 90% | 97% |
| -51 dBFS | 기준 0.5 | 83% | 28% | 0% |
| -51 dBFS | 기준 0.35, +20 dB | 91% | 91% | 60% |

마이크마다 말소리 크기가 다르므로, 등록은 말소리가 약 -19 dBFS 로 VAD 에 들리도록 마이크별 증폭(1~30배)을 정한다. -39 dBFS 로 들리는 헤드셋이면 위 +20 dB(10배)와 같다.

## 한계

- 사용자 말이 다른 사람 말과 겹치면 Claude 가 섞어 받아쓰고, hook 은 전체를 통과시키거나 막을 뿐 일부만 뺄 수 없다.
- 사용자가 키보드를 치는 1초 안에 다른 사람 말이 자동 전송되면 통과한다.
- 본인 말을 판정기가 못 들으면 자동 전송이 막힌다. 글은 `voice-blocked.jsonl` 에 남고, 직접 Enter 로 보낸 말은 막히지 않는다.
- 본인이 지시가 아닌 잡담을 해도 화자 판정으로는 막을 수 없다.
- 실행 중인 Claude Code 세션이 hook 추가를 바로 읽지 않으면 `/hooks` 확인이나 세션 재시작이 필요하다.
