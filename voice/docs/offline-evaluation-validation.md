# Offline evaluation equivalence

`voice/tests/native-eval-differential.mjs` runs the unchanged public baseline evaluation functions and the native evaluation commands sequentially. It uses the model runner's existing disposable Python environment, model files, sherpa C API, native BLAS and checksum-pinned public speech. Additional evaluation-only wheels and six untouched original source files are pinned in `voice/tests/eval-probe-assets.json`. Neither runner nor its Python dependencies are included in an installed plugin.

```sh
node --test voice/tests/native-eval-differential.test.mjs
node voice/tests/native-eval-differential.mjs \
  --binary rust/target/debug/herdr-theme \
  --work-dir .migration-oracle/voice-model-differential
```

Use `.exe` on Windows and the same Python 3.12 options as the model runner. No Rust build, microphone, app focus, plugin installation or service operation is performed. `--only models`, `--only vad`, `--only chain` and `--only models_cli` select diagnostic subsets; a subset alone cannot establish a complete pass. `--reuse-oracle` reuses an original result only when its input key and retained result/CLI checksums match. This avoids repeating an unchanged original model run during a native implementation fix.

The generated Parquet file contains eight synthetic identities, each with sixteen five-second PCM16 WAV clips. Each clip is a deterministic circular shift of the first five seconds of the pinned public recording. Speaker rows deliberately arrive in order `3, 1, 7, 0, 6, 2, 5, 4`: the original VAD experiment preserves encounter order before its seeded permutation, while model and gate-chain trials sort speakers. This supplies the original minimum of seventy-five seconds per speaker and enough held-out clips without reducing enrollment, trial, scene or VAD loop counts. It exercises data loading and every original evaluation path. These identities do not represent eight real speakers and provide no speaker-discrimination accuracy evidence.

The runner compares model metrics at an absolute limit of `1e-12`, VAD JSON metrics at the same limit, and gate-chain/VAD stdout exactly. It exercises both the single-model worker and the outer multi-model CLI, including child-process execution and output-file creation. VAD result-file bytes, stderr, counters, booleans, field sets, array lengths and subprocess exit statuses must match. Result files preserve the original one-space JSON indentation, ASCII escaping, platform text newlines and absence of a final newline. Model time and process memory are measured independently and checked for valid nonnegative values; only those telemetry numbers are replaced when comparing outer-CLI stdout and result-file bytes. Missing, empty and non-directory model inputs must produce no output and preserve any preexisting output file, as the original glob-based CLI does.

On Windows, the original Unix-only `resource` import uses an explicitly recorded zero-telemetry shim. A rejecting sounddevice import shim makes any attempted microphone operation fail, and reference stdout explicitly uses UTF-8. The outer-model oracle launches its unchanged original worker through the same isolated bootstrap so that the Windows import shim also applies to that child. These adaptations do not change the original numerical functions, but do not establish original Windows CLI availability.

The work directory's `eval/` folder retains original/native stdout, stderr, exit status, JSON results and `eval-differential-summary.json`. The summary records executable, Parquet, source, model and library checksums. Failures remain failures; a new fixture is not accepted by changing its expected numeric values.

The first Windows comparison exposed an actual far-channel drift of up to `1.87e-7` in model score metrics, although the near-channel results and error-rate counters matched. The original SciPy convolution uses real fast lengths and transforms float32 speech and float64 room response separately. The earlier native implementation used a power-of-two length and converted speech to float64 first. The native convolution now builds the exact PocketFFT header revision used by SciPy 1.16.0, preserving both operand precisions. Source, license and SHA-256 provenance are retained under `rust/vendor/pocketfft/`.

`voice/tests/fixtures/evaluation-native-windows-x64.json` records the post-change Windows x64 comparison on executable SHA-256 `87d3a959fc3d2d8aaf93ac5f0ea4821962dd20f764bc32202f3f356471b493d5`. All four evaluation cases passed with the native child's PATH empty. All compared numerical metrics matched with maximum absolute difference zero. VAD and gate-chain stdout/stderr matched exactly; VAD result-file bytes matched exactly; outer-model stdout and file bytes matched after replacing only the independently measured timing/RSS numbers. Empty, missing and non-directory model inputs preserved the original exit/output behavior. The previous failed comparison is retained separately as evidence; no tolerance or expected metric was changed.

Run these checks on each supported platform after the single-job native build, alongside the separate fixed-audio model comparison and [native audio/Parquet type comparisons](native-audio.md). Upload the `eval/` JSON reports on success and failure. Actual microphone/device/focus acceptance remains separate macOS work.
